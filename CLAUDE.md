# Workout Path

A personal workout web app (React, built with Vite, hosted on GitHub Pages), used on a MacBook and an iPhone (installed to the Home Screen). See `PLAN.md` for the concepts, screens and milestones.

## How the site is built

Vite + React 19 + TypeScript. Node 22 (`.nvmrc`). On this Mac `npm start` runs `nvm use` and then the dev server; `npm run dev` alone runs the local server (also reachable from the iPhone on the same Wi-Fi); `npm run build` typechecks and builds into `dist/`.

- Routing is the URL hash: `#today`, `#workouts`, `#workouts/<id>`, `#routines`, `#routines/<id>`, `#catalog`, `#catalog/<exercise id>`, `#history`, `#history/<session id>`, `#history/exercise/<exercise id>`, `#play/<workout id>` (`readHash()` in `src/App.tsx`; everything after the first `/` is `sub`).
- `src/views/`: `Catalog` (list + detail panes), `ExerciseDetail`, `Workouts` (list; `#workouts/<id>` opens `Builder`), `Builder`, `Player`, `Routines` (list; `#routines/<id>` opens the editor), `Today`, `History`, `ExerciseEditor`. `src/components/`: icons, `ExerciseBrowser` (search + filters + grouped list, shared by the Catalog and the builder's picker), `Toast`, and `ui.tsx` (`ChipGroup`, `Seg`, `Stepper`, `NumberInput`, `Menu`, `Select`, `useSessionState`, `useMedia`).
- Workouts: a workout is a list of blocks. A `straight` block holds exactly one exercise (its own sets and rest). A `superset` / `circuit` block holds 2+ exercises done one set each per round; the block's `rounds` and `restBetween` apply, item `sets` is ignored and item `rest` is the rest after that exercise. `tidy()` in `src/lib/workout.ts` keeps this true after every edit (a group of one becomes a single exercise). Grouping uses the max of the sets as rounds; ungrouping gives each exercise the rounds as sets.
- Deleting a workout sets `deletedAt` (it stays in state, hidden), so history keeps its name and the delete can sync. `liveWorkouts()` lists the rest. Destructive builder actions show an Undo toast (`showToast` in `src/lib/toast.ts`) that restores a snapshot of the workout.
- Builder: tap a row to edit it (one open at a time). Reorder by dragging the grip handle (`src/lib/useDragSort.ts`, pointer events, works with touch and mouse, auto-scrolls) or with Move up / down in the row menu. The picker is a full-screen sheet below 1024 px and a side pane from 1024 px, where exercises can also be dragged into the workout (HTML5 drag type `application/x-workout-exercise`; drop on a group to join it). Changing an item's variation resets its dose to that variation's default (and drops "Timed"). Rest steppers step 5 s up to 30 s, then 15 s (`restStep` in `ui.tsx`), so Tabata's 10 s rest fits.
- `src/lib/filter.ts`: catalog search + filters (OR within a group, AND across groups; search words must all match name, aliases, variations, section, equipment or focus words (`FOCUS_TERMS`, e.g. "isometric", "stretch"); a trailing "s" is optional). The mode filter also matches variations that override the mode. The focus chips (All · Strength · Isometric · Mobility · Flexibility · Cardio) sit above the list, one at a time, and aren't counted on the Filters button. Filters live in `sessionStorage` (`workoutPath.catalogFilters`), not in app state.
- `src/lib/format.ts`: `formatDose()` ("3 × 45 s", "10 reps", "20 min", "per side", "· 12 kg").
- `src/state/store.ts`: the single app state (shape in `PLAN.md`), `useAppState()`, `update(fn)`; saved to `localStorage` key `workoutPath.v1`. `src/state/actions.ts`: every state change goes through here. Ids come from `uid()` (`crypto.randomUUID` is missing on the plain-http LAN dev server).
- Layout: below 768 px a top bar + bottom tab bar (5 tabs) and one pane (list or detail); from 768 px a sidebar; from 1024 px the catalog is two panes that scroll on their own. Catalog keyboard on the Mac: `/` search, ↑ ↓ move, Esc close.
- Player (`#play/<workout id>`, `src/views/Player.tsx`, full screen without the tab bar / sidebar): `startWorkout()` (call from a tap) flattens the workout into steps (`buildSteps()` in `src/lib/player.ts`: work steps per set / round / side, rest steps between; per-side timed sets get a 5 s "Switch sides" rest; no trailing rest). The run (`Run`) is kept in `localStorage` key `workoutPath.run` (`src/state/run.ts`, not synced) so a reload or the app being closed resumes it; a Resume bar shows on every tab while one exists.
  - Timers are timestamps (`endsAt`, `left` while paused, `lead` = 3-2-1 get-ready). `catchUp()` applies every timer that ended, each at its own end time, so time away is replayed correctly. A rest always starts by itself; a timed set starts by itself after a rest (no lead) or straight after another set (5 s lead), otherwise on Start (3 s lead). Reps sets: count with − / +, then Done.
  - Logging: a timed set that runs out logs its target; End set logs what was done (0 = skipped); Skip logs skipped; Back goes to the previous set to redo it (its log is overwritten). Ending early → summary with Keep going. Save adds a `Session` (with `workoutName`) and clears the run.
  - Sound (`src/lib/audio.ts`): ticks at 3-2-1, a go tone when work starts, a done tone when a timed set ends; unlocked by the first tap (iOS), muted by the speaker button (`settings.beeps`). No sounds while catching up after time away. Screen stays on via Wake Lock (`src/lib/wakeLock.ts`), re-taken on return to the page. Mac keys: Space = main button, → skip, ← back.
- Routines (`src/lib/routine.ts`, actions in `actions.ts`): one is followed at a time (`activeRoutine`). Weekly: `days[0..6]`, 0 = Monday, null = rest day; shown in the device region's week order (`weekStart()` via `Intl.Locale` week info, Monday if unknown). Rotation: `order` (workout ids, repeats allowed) and `pos` (index of the next one). Saving a session moves `pos` on when it's the active rotation's next workout and at least one set was done (`addSession`); "Skip to next" and "Make this next" set it by hand; reordering keeps the marker on the same workout. Deleted workouts are skipped (rotation) or count as rest (weekly). Deleting a routine sets `deletedAt` (Undo restores it and whether it was followed).
- Today (`src/views/Today.tsx`, `todayPlan()`): the followed routine's workout for today (weekly) or next (rotation) with Start; a rest day shows the next scheduled day; done today shows a check and what's next. Weekly gets a week strip (done / today / missed), rotation a sequence strip. Then Quick start (every workout) and the last workout. No routine → set one up (or build a first workout).
- History (`src/views/History.tsx`, helpers in `src/lib/history.ts`): Workouts / Exercises toggle; stat tiles (this week from the region's week start, last 30 days, all time); a 12-week activity grid (a filled cell = a day with a saved workout); saved workouts by month. A saved workout's page edits RPE and note and deletes with Undo (`deleteSession` drops it from `sessions` and records the id in `sessionsDeleted` for sync; Undo removes the record). An exercise's progress page charts best set / total / weight per workout (`LineChart`), with stat tiles and every workout listed below (the chart's table view). Variations are separate lines when their modes differ (push up reps vs static hold); when all share a mode there's also "All variations".
- `src/components/LineChart.tsx`: one-series SVG line over time, no library. Follows the dataviz specs: 2px line, ~10% area wash, r=4 dots with a 2px surface ring (dots only up to 40 points), solid hairline grid, end value labelled, crosshair + tooltip on pointer / touch / ←→ keys. Colour token `--chart` (light `#C2410C`, dark `#E8661C`, both validated against the card surface).
- The exercise page's "My history" shows best reps / hold / minutes / kg and the last session's sets (`groupSets()` / `setsLine()` from `Player.tsx`) and links to its progress page.
- Sync (`src/state/sync.ts`, same pattern as piano-path): one private GitHub Gist with file `workout-path.json`, found by filename or created on first connect. The token (classic, `gist` scope; the Piano Path token works too) is pasted per device in the Sync & backup sheet (`src/components/DataSheet.tsx`, opened from the status pill in the top bar / sidebar) and kept in `localStorage` key `workoutPath.gist`; never put it in code. Syncs on start, after a local change (2 s after the first, then at most one write a minute while editing: `PUSH_GAP_MS`; leaving the app or Sync now sends right away); while a change waits the status is `pending` ("Saved here · syncing soon", steady dot) (`onLocalChange` in `store.ts`), on return to the app, on reconnect, and every 2 min while visible. The workout in progress (`workoutPath.run`) is not synced. Errors keep GitHub's message (`HttpError.ghMessage`, headers); `explain()` turns them into a short pill text + a `detail` for the sheet. Hourly limit (403/429 with `x-ratelimit-remaining: 0`) or "slow down" (secondary limit, `retry-after` or doubling from 1 min up to 15) set `status.retryAt`: automatic syncs wait until then and one is scheduled for it; "Sync now" ignores it. The sheet shows requests left this hour (`status.quota`, from every response's rate-limit headers). Reads send the last ETag (`If-None-Match`, `lastRead` holds the ETag + file text, also taken from a write's reply); an unchanged gist answers 304, which GitHub doesn't count toward the 5,000/hour limit shared by every app on the account.
- Merge (`src/lib/merge.ts`, type-only imports so it can be tested alone): workouts, routines, custom exercises per item by newer `updatedAt` (soft deletes win the same way); sessions are the union by id minus deleted ones, where `sessionsDeleted` holds `{ id, at }` and a delete only wins over a session not touched after it (restore / edit set `session.updatedAt`, so Undo after a sync still works); settings and `activeRoutine` from the copy with the newer top-level `updatedAt`. Every edit must stamp the item's `updatedAt` (the `edit` / `editRoutine` helpers do).
- Backup (`src/lib/backup.ts`): Export writes the whole state as JSON (`workout-path-backup-YYYY-MM-DD.json`; the share sheet on touch devices, a download elsewhere; the token is never in it). Import checks it's a backup, then merges it in (`replaceState(…, { local: true })`, so it syncs out); nothing is removed.
- PWA: `public/manifest.webmanifest`, `public/icon.svg`, PNG icons in `public/icons/` (180 px is the iOS apple-touch-icon; the PNGs are full-bleed with the kettlebell inside the maskable safe zone), `public/sw.js` (production only; network first for the page, cache first for hashed assets).
- Deploy: `.github/workflows/deploy.yml` builds and publishes to GitHub Pages on every push to `main` (Pages source = GitHub Actions). Live at https://itzik-a.github.io/workout-path/.

## Data

- `src/data/catalog.ts`: `SECTIONS` and `EXERCISES` (the built-in catalog), label maps (`REGION_LABEL`, `MODE_LABEL`, `EQUIPMENT_LABEL`) and `HOME_EQUIPMENT` (what I have; default for `settings.equipment`). Sections group by type of training; `regions` (upper / lower / core / full) is the body-region filter. Focus (`focusOf()`: strength / isometric / mobility / flexibility / cardio) cuts across sections: an exercise's `focus` if set, else from its section (strength sections + physio reps → strength; a hold in a strength or physio section → isometric; mobility / flexibility / cardio sections → their own). Set `focus` on an exercise when that default is wrong (stretches in mobility or physio, the glute bridge, the Cossack squat). Custom exercises pick it in the editor.
- **Never rename or reuse an exercise or variation `id`**: workouts, routines and sessions are keyed by id. Add new ids instead. Custom exercises made in the app use ids prefixed `u-` (variations `v-…`). To drop a built-in exercise, set `retired: true` instead of deleting it: `allExercises()` (catalog, picker) hides it, `getExercise()` still resolves it so workouts and history keep working, and its page says "Retired". Templates must not use retired exercises.
- Custom exercises (`state.customExercises`, editor `src/views/ExerciseEditor.tsx` at `#catalog/new` and `#catalog/<u-id>/edit`): same shape as catalog exercises plus `updatedAt` / `deletedAt` (soft delete, synced per item). `allExercises()` hides deleted ones; `getExercise()` still resolves them so workouts and history keep their names.
- My notes & links (`state.exerciseNotes[exerciseId]` = `{ note?, links?: {url, label?}[], updatedAt }`): on every exercise page; links also show under the cue in the player. Merged per exercise by `updatedAt`. No photos (they'd bloat the synced gist); links cover videos and photos hosted elsewhere. Built-in exercises can also carry `links` in `catalog.ts` (how-to videos): shown in a "How to" card on the exercise page and before my links in the player.
- Templates (`src/data/templates.ts`, `fromTemplate()` in `workout.ts`, sheet `src/components/TemplatesSheet.tsx`): starter workouts from catalog ids with dose overrides; picking one creates a normal workout ("Name 2" if the name is taken). Every id must exist and need only `HOME_EQUIPMENT`. `timed: true` on a template item makes a reps exercise timed (`seconds`), as in the Tabata template.
- Progressions (`src/data/progressions.ts`, logic `src/lib/progress.ts`): ladders of an exercise's variations, easiest first, each with a target in that variation's unit (no mixing reps and seconds in one ladder). `suggestFor(item)` looks at the last `READY_STREAK` (2) workouts with that exercise + variation: if the item is on a ladder step that isn't the last and its best set hit the step target in both → "move up" (applies `setVariation`, dose resets to that variation's default); else if every set in both reached the planned amount with none skipped → "increase" (`bump()`: +1 rep, +2 from 10; +5 s hold, +10 s from 60; +1 min). Shown under builder items and in the player summary's "Next time" (which counts the workout just done). "Not now" stores the suggestion's key in `item.skipSuggest`. The exercise page shows the ladder with targets, bests and "You're here".
- Modes: `reps` (count), `hold` (seconds), `time` (minutes). A variation can override the exercise's mode and dose. `perSide` means the dose is per side.
- Interval holds: a hold (or timed) item can have `repeats` (≥ 2) and `repeatRest` ("Intervals" chip in the builder): each set is that many holds of `seconds` with `repeatRest` s between, e.g. "3 × (5 × 10 s on / 5 s off)". A `Dose` can carry the same fields as a variation's default (the Nordic / reverse Nordic holds). `buildSteps()` makes each hold its own work step (`rep: {i, n}`, "Hold 2 of 5") with "Short rest" steps between; the next hold starts by itself after the short rest. Each hold is logged as its own `SetLog` with `rep`, so best = best hold and suggestions bump the hold seconds; `setsLine()` shows one set's holds as "5 × 10 s" (or "(10 s, 10 s, 6 s)").
- Timed items (intervals / Tabata): a workout item of a reps exercise can be made timed ("Timed" chip in the builder, `setTimed()`): `item.mode = "hold"` with `seconds`. `itemParts()` returns `mode` (effective) and `base` (the variation's). The player copies the override onto each logged set (`SetLog.mode`), and `setMode()` reads it, so history charts timed sets as their own line ("Standard (timed)"), the summary groups them apart, and suggestions only compare like with like (timed items get "increase", never a ladder move-up; ladders ignore timed sets).

## Rules for changes

- Design mobile-first (iPhone ~390 px), tap targets at least 44 px, safe-area padding. Below 768 px: bottom tab bar. From 1024 px: sidebar + two panes. Check both.
- Colours only from the CSS tokens in `:root`; light and dark themes must both stay readable.
- Audio starts only from a user tap (iOS). Timers use timestamps so they survive the screen locking.
- New state fields must be optional in `normalize()` so older saved copies still load.
- Run `npm run build` after edits; it must pass with no type errors.
